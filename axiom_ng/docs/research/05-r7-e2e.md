## Mini-Go-Runner (commit under `cmd/feasibility/minirunner/`)

`minirunner.main` — a standalone Go HTTP server:
- `/v1/embed`: `onnxruntime_go` BGE-M3 dense encoder (pinned tokenizer + HF
  reindex); returns ≥ `EMBEDDING_SHAPE_MISMATCH` guards compatible with
  `internal/processor/embed_rerank.go`.
- `/v1/rerank`: `onnxruntime_go` bge-reranker-v2-m3 logits → sigmoid; XLM-R pair
  form `[CLS] q [SEP] p [SEP]`; same contract shape as §7a.
- `/v1/health`. **No `/v1/sparse`** (Go sparse output extraction is blocked,
  Block 3) — the ±sparse bench rows are dropped per the issue.

Verified live:

### Root cause found & fixed: mini-runner query embedding bug
The first Go R7 run showed dense P@5 **0.080** vs Python **0.536** — a false alarm.
Root cause: `minirunner` never called
`tok.WithPostProcessor(BertStylePostProcessor(0,2))`, so its **query** ids were
encoded WITHOUT the `<s>…</s>` wrapper Python uses → Go query embed cosine to
Python was only **0.509** → dense retrieval collapsed. Fixed in `minirunner/main.go`
(commit `19f4236`). After the fix, Go-vs-Py **query cosine = 1.0**.
