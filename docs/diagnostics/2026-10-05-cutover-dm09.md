# DM09 cutover rehearsal: the full window and the way back

Date: 2026-10-05  
Scope: DM09 (#318) — automated cutover + rollback, dev rehearsal against a restored production copy  
Result: full window green end-to-end (health + search smoke after the switch, shadow re-run green IN window); pre-write and post-write rollback rehearsed with an idempotent re-apply; stuck lease converged under the documented `cancel` choice; a mid-cutover failure resumed from its exact gate with zero re-runs

## Provenance

Everything below ran from the strand build of `axiom data cutover` /
`axiom data rollback` (commit `8fe02e12` + the lease-convergence fix
that followed it — the rehearsal itself caught the pre-fix dishonesty,
see "Caught by this rehearsal"). The pull point: a read-only
`pg_dump` of the production database, restored as a scratch mirror
copy (production untouched and still serving throughout). The corpus
at pull: 370 documents, 983 items, 443 attachments, 636 jobs, 361
source revisions — the familiar DM08 scale, plus one window-drift
seed (a new item) and one synthetic stuck lease.

## Procedure

1. **Pre-window loop (the rehearsed DM04/DM08 shape):** full export
   from the mirror copy → import into the prepared target (schema-only
   restore of the same pull, ledger rows carried) → shadow green
   ([dm09-pre-shadow-report.json](data/dm09-pre-shadow-report.json)).
2. **Dry-run sonde:** `axiom data cutover --plan …` without the
   confirmation flag — plan, baseline, every DSN verified; zero
   mutations (no run dir, no config row, no DDL, target counts
   unchanged).
3. **The window:** one stuck lease planted (`claimed`,
   `lease_until` +40s, worker `dm09-stuck-worker`), plan choice
   `cancel`, then `--require-confirmation`.
4. **Rollback rehearsal:** immediately after the window (pre-write),
   then after two post-write mutations on the target (a changed row
   and a new row), then a third invocation for the idempotency
   witness.
5. **Mid-cutover failure + resume:** a second window whose restart
   health check pointed at a closed port; after the failure, the port
   was opened and the SAME run resumed with `--run-dir`.

## The way back

- **Pre-write** (nothing written since the switch): rollback verdict
  `pre-write` — the target was re-indexed and compared byte-exactly
  against the freeze anchor (the comparison IS the evidence), config
  reverted from the backup, no shadow tables created
  ([dm09-rollback.json](data/dm09-rollback.json), first invocation).
- **Post-write** (one changed row + one new row on the target):
  verdict `post-write`; the reverse delta landed in
  `cutover_shadow_zotero_items` on the mirror copy — 2 rows, tagged
  `applied_run` ([dm09-reverse-delta-report.json](data/dm09-reverse-delta-report.json));
  the changed row carried its NEW payload (v100000), the new row its
  full content, both FK-free (the shadow tables are `LIKE` the live
  table without constraints).
- **Idempotency:** a third invocation re-decided post-write and
  re-applied: **0 new rows, count stable at 2** — identical rows skip,
  no duplicates possible.

## Mid-cutover failure → exact resume ([dm09-resume-run.json](data/dm09-resume-run.json))

The restart gate failed against the closed port after freeze, import,
FK drops, and config switch had completed. The resume invocation:

- skipped every completed gate (the run log line lists them),
- the maintenance stop-marker file fired **exactly once** across both
  invocations,
- the freeze cutoff was **not recomputed** (`14:04:38.208720Z` before
  and after),
- the failed gate re-ran once its cause was removed (port opened), and
  the window completed through shadow and re-enable.

## Sondes with teeth (also in CI)

- **Confirmation gate:** without `--require-confirmation`, nothing
  moves — asserted over run-dir absence, FK count, target counts, and
  config-file absence (automated in `internal/cutover`).
- **Stuck lease, other choices:** `abort` fails the run naming the
  lease (row untouched); `wait` with a drained budget fails with the
  honest "did not converge" diagnosis.
- **Stale baseline:** a window whose baseline no longer matches the
  target state is refused at the delta-import precheck ("the delta
  base is violated — the window does not improvise").

## Caught by this rehearsal (fixed before landing)

The first window run recorded the lease outcome as `cancelled` while
the job row still read `claimed`: the drain loop returned on the
empty active-lease poll BEFORE applying the expired-cancel
terminalization. The CI test had passed by timing luck (its poll
interval happened to hit the loop-bottom convergence). Fix: the
cancel path converges expired cancellations on the empty-set exit
too; the row now matches the recorded outcome, deterministically.
That is what general rehearsals are for.
